# Отчёт по рефакторингу

## Какие функции выделены
- `load_data` — читает `features.parquet` и `churn_truth.csv`, соединяет по `subscriber_key`;
- `preprocess` — выбор числовых признаков, деление 60/20/20, заполнение пропусков, масштабирование;
- `train_model` — обучение RandomForest;
- `evaluate` — ROC-AUC (val, test) и F1 (test);
- `save_artifacts` — сохранение модели, скалера, списка признаков и метрик;
- `main` — читает конфиг, настраивает логирование и вызывает этапы по порядку.

## Что вынесено в config.json
Пути к данным; параметры деления (`test_size`, `val_size`, `random_state`) и список исключаемых колонок; гиперпараметры модели; папка и имена артефактов; уровень, формат и файл логирования. В коде этих значений нет.

## Логирование
Модуль `logging`: сообщения идут в консоль и в `pipeline.log`. Логируются размер данных, число признаков, метрики, сохранение артефактов и время работы. Ошибки пишутся через `logging.exception` и пробрасываются дальше.

## Идемпотентность
`save_artifacts` удаляет старую папку `artifacts/` и создаёт её заново, поэтому повторный запуск не оставляет лишних файлов и не создаёт дубликатов. Фиксированный `random_state=42` даёт одинаковые метрики. Проверка: конвейер запущен дважды подряд, набор файлов и метрики совпали.

## Docker
Dockerfile: образ `python:3.13-slim`, установка `requirements.txt`, копирование кода, `CMD ["python", "main.py"]`. Образ собран командой `docker build -t churn-pipeline .`, контейнер запущен командой `docker run --rm -v "$(pwd)/artifacts:/app/artifacts" churn-pipeline`. Конвейер отработал внутри контейнера: в консоли появился лог всех этапов, а в папке `artifacts/` на хосте появились 4 файла.

## Сложности
- Пути ноутбука (`/content/...`) заменены на относительные.
- Не все колонки числовые: текстовые идентификаторы и категории исключены через конфиг.
- Признаки унаследованы из занятия 5.1: в них есть утечка (`days_since_last_call`), поэтому метрики завышены.
